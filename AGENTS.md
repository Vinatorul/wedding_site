# Свадебное приглашение Саши и Сони

Это приглашение на 16 октября 2026 года: страница без сборки и небольшой Python-сервер для сохранения анкеты в SQLite. Проект развивается небольшими правками по референсу и пожеланиям владельца. Перед работой прочитай [README.md](README.md), а для изменений деплоя — [DEPLOYMENT.md](DEPLOYMENT.md); проверь текущие файлы и `git status`. Новые указания владельца важнее зафиксированных здесь решений.

Несмотря на название, `dist/` содержит исходники: редактируй их напрямую. Сборки фронтенда и `package.json` нет. Не добавляй их для обычной правки текста или оформления. Сервер использует Flask и Gunicorn; зависимости устанавливаются из публичного PyPI, npm-инструменты — из публичного реестра, заданного в `.npmrc`.

`main.js` подставляет строки из `content.js` через `textContent`. При изменении такого текста обновляй и значение в JS, и запасной текст в HTML. Расписание и подписи карточек находятся непосредственно в HTML.

Для локального просмотра вместе с рабочей анкетой установи зависимости по [README.md](README.md) и запусти из корня репозитория:

```sh
.venv/bin/gunicorn --chdir backend --bind 127.0.0.1:4173 'app:create_app()'
```

Открой `http://127.0.0.1:4173/`. Если подходящий сервер уже работает, используй его. Обычный `python3 -m http.server` показывает страницу, но не обслуживает API анкеты. После изменения файлов страницы обновляй вкладку: автоматической перезагрузки нет. После изменения Python-кода перезапусти сервер. В HTML у скриптов есть параметры версии; если браузер продолжает показывать старый JS, проверь кэш и обнови версию изменённого скрипта.

## Принятые решения и причины

- **Коллажный стиль сохранён из референса, палитра — только бургунди.** Владелец убрал выбор темы. Цвета задаются CSS-переменными; переключателя, `theme.js` и осенней палитры нет. Старые ссылки с `?theme=…` открывают тот же вариант бургунди.
- **Акцентный шрифт — CCZoinks, основной — Manrope.** CCZoinks выбран после примерок Corvetta и Ura Bum Bum. Шрифты лежат локально. Заголовки разделов приведены к размеру «Друзья и родные!» через `--section-title-size`: 61 px на широком экране и 46 px до 760 px. «Друзья и родные!», «Где встречаемся?» и «Команда» начинаются с заглавной буквы; не переводи их в капс.
- **Тексты постепенно сокращали.** Не возвращай удалённые общие фразы вроде «мы женимся», «сохраняйте дату» и верхний блок «это любовь / я буду» без нового запроса. Присланные владельцем формулировки сохраняй дословно.
- **Локации оформлены как фотографии в белых рамках.** По просьбе владельца убраны цветные пятна под ними и наклон самих карточек. Подписи находятся внизу рамки, обычным шрифтом: «Загс / Усадьба Воронцово» и «Ресторан / Винил и вино». Используются `vorontsovo-photo.png` и `vinyl-wine-photo.png`; старые вырезанные изображения в assets не являются текущими фото локаций. Фото пары остаётся вырезанным PNG с тенью; форма сердечка взята из присланного образца и хранится в SVG.
- **Яндекс Карты должны быть живыми.** Владелец отдельно отверг скриншот вместо виджета. Кнопка «Где это?» переворачивает карточку к iframe, «Назад» возвращает фото. Подписи на обеих сторонах совпадают. В карточках наклонены только кнопки. Карты и фото локаций обесцвечены CSS-фильтром для общего стиля. Отдельные виджеты и дополнительные кнопки открытия карт были убраны.
- **Время в расписании имеет отдельную достаточно широкую колонку.** После замечания к `00:00` её расширили до 120 px на широком экране и 108 px на мобильном, запретив перенос самого времени. При изменениях шрифта или сетки проверяй этот пункт и длинные заголовки. Текущие часы — 11:20, 11:40, 13:30, 15:00, 19:00 и 00:00; у последнего пункта `datetime` относится уже к 17 октября.
- **«Вишлист» — действующая ссылка акцентным шрифтом.** Последний выбранный вариант: 18 px рядом с основным текстом 16 px, цвет остального текста, без подложки и подчёркивания, затем подсказка «(нажми на слово вишлист)». Более ранний бордовый вариант отменён. `gifts` содержит только начало абзаца: `data-content` стоит на соседнем `span`, а не на всём `p`, иначе `textContent` удалит ссылку.
- **«Команда» стоит перед анкетой.** Ведущий Андрей и координатор Татьяна оформлены в том же стиле белых рамок; на телефоне карточки идут друг под другом. Фото, телефоны и значки контактов пока намеренно оставлены заглушками. Кнопки Telegram и WhatsApp отключены, фиктивных ссылок нет. `.team-card` отделена от `.venue-card`, чтобы статические карточки команды не получали поведение переворота.

## Интерактивность и следующие шаги

В карточках локаций уже предусмотрены `inert`, `aria-hidden`, перенос фокуса и `prefers-reduced-motion`. Сохраняй эти свойства при изменениях. Анимация переворота временная: после её завершения на `.venue-card-inner` не остаётся трансформации. Проверяй не только показ оборота, но и управление картой внутри iframe. Для загрузки карт нужен интернет.

Анкета отправляет JSON через `POST /api/rsvp` на тот же сервер, который выдаёт страницу. Успех показывается только после записи в SQLite; при ошибке введённые поля сохраняются, кнопка снова доступна. На время запроса кнопка отключена, чтобы повторный клик не отправил ещё одну анкету. Каждая завершённая отправка создаёт отдельную строку — обновления предыдущего ответа и защиты от повторной отправки после сбоя связи нет. Удалены надпись «вот тут ↗» и пояснение о демонстрационном режиме.

Текущие поля: имя, спутники, пять вариантов участия, напитки свободным текстом и многострочное поле о еде. Имена полей API — `name`, `companion`, `attendance`, `drink`, `food`; пределы текста в HTML и на сервере должны совпадать. Значения участия — `yes`, `ceremony`, `buffet`, `banquet`, `no`; при `no` отключается поле напитков и отправляется пустая строка. Сохраняй связь `label` с полями и проверку имени, в том числе строки из пробелов. При изменении полей сверяй форму, отправку, серверную проверку, схему базы и CSV.

Ответы читаются только скриптом выгрузки на виртуалке: владелец выбрал локальный CSV вместо страницы администратора. Скрипт открывает базу только для чтения; в CSV остаются коды участия, время в UTC и многострочный текст. Публичного API чтения ответов нет. Локально база находится в `backend/data/rsvp.sqlite3`, на сервере — в `data/rsvp.sqlite3` внутри каталога деплоя. `RSVP_DB_PATH` и `SITE_ROOT` задают путь к базе и корень страницы. Базу и выгрузки не добавляй в Git и в `dist/`.

Деплой собирает свой Python-образ и пересоздаёт только контейнер приглашения без опубликованных портов. Общий Caddy отправляет ему запросы на внутренний порт 8000. Каталог сайта монтируется только для чтения, `data/` — отдельно для записи под UID/GID 10001, вне сменяемых релизов. Поэтому ответы остаются при обновлении. Не удаляй `data/` при очистке старых файлов. При ошибке скрипт возвращает прежний релиз и контейнер и пытается восстановить Caddy; ошибки самого отката выводятся отдельно.

Общий Caddyfile нужно сохранять на месте, без замены inode: прокси может монтировать отдельный файл. Меняется только блок приглашения, общий прокси не перезапускается. Маршрут `/rover/`, если он уже включён, сохраняется из этого блока при следующих обновлениях; параметры upstream и сети передаются парой. Скрипт проверяет подключение прокси к сети игры, но не подключает её сам. Адреса владельца и параметры виртуалки передавай при запуске, не записывай в репозиторий.

Осталось получить у владельца фото и контакты команды и уточнить дресс-код. Публикация сайта — отдельная задача: наличие репозитория на GitHub само по себе не означает, что сайт размещён в интернете. Не выдумывай контакты.

## Как проверять и сохранять изменения

- Продолжай работу в этом репозитории. Владелец попросил работать с теми же файлами, а не создавать копии проекта для каждой правки.
- Делай отдельный локальный коммит после каждого большого изменения. Не переписывай предыдущие коммиты. `origin` указывает на `git@github.com:Vinatorul/wedding_site.git`; push выполняй по явному запросу, а не автоматически после каждой правки.
- **Архив и длинный скриншот обновляй только по отдельному запросу.** `sasha-sonya-16-10-2026.zip`, `previews/` и `dist/mobile-preview.jpg` могут отражать прежнее состояние. `dist/mobile-preview.html` показывает сохранённую картинку, а не живой сайт; для проверки используй `dist/index.html` через локальный HTTP-сервер.
- Для Python есть проверки через `unittest`: API и CSV используют настоящие временные базы SQLite, тесты деплоя моделируют команды Docker и используют временные файлы. Они не подтверждают запуск живого Docker/Caddy. Настроенного CI нет. Форматируй только изменённые файлы: Prettier 3.6.2, для JS — ESLint 8.57.1 с проверками неопределённых и неиспользуемых переменных, для Python — Ruff 0.13.2. Для небольшой правки текста или CSS достаточно форматирования и просмотра; запускай тесты только затронутого поведения.

Примеры точечных проверок из корня репозитория; набор файлов выбирай по своему изменению:

```sh
npx --yes prettier@3.6.2 --check dist/index.html dist/styles.css AGENTS.md
npx --yes eslint@8.57.1 --no-eslintrc --env browser,es2021 --rule 'no-undef:error' --rule 'no-unused-vars:error' dist/main.js
git diff --check
```

После установки зависимостей из README примеры проверок Python:

```sh
.venv/bin/python -m unittest discover -s tests -p test_rsvp_api.py -v
.venv/bin/python -m unittest discover -s tests -p test_export_rsvp.py -v
.venv/bin/python -m unittest discover -s tests -p test_deploy_vm.py -v
```

Ruff не входит в зависимости сервера. Используй уже установленную утилиту либо установи указанную версию из публичного PyPI в отдельное окружение; для изменённых Python-файлов выполни `ruff format` и `ruff check`.

Для правок вёрстки проверь затронутый блок в браузере на ширинах 320–390 px и около 1280 px: нет горизонтальной прокрутки, обрезанного текста и наложений. При правках интерактивности проверь соответствующие действия: переворот обеих карточек и возврат, кнопки карты, выбор участия и валидацию анкеты. После проверки убери временный размер окна и тестовые значения полей. Для изменения только этого документа достаточно проверки фактов, ссылок и Markdown; запускать сайт не требуется.
