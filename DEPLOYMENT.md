# Деплой на виртуалку с Docker и Caddy

Скрипт `scripts/deploy-vm.py` размещает приглашение за уже работающим Caddy. Для сайта создаётся отдельный контейнер без открытых наружу портов. Скрипт добавляет в общий Caddyfile только блок нового домена и применяет его через `caddy reload`. Остальные сайты, контейнер прокси и его сертификаты остаются на месте.

Нужны Linux, Git, Python 3.10 или новее и работающий Docker. Общий Caddy должен быть запущен в контейнере, подключён к Docker-сети и читать Caddyfile из файла или каталога, смонтированного с виртуалки. Для первого запуска нужен доступ к Docker Hub: используется официальный образ `docker.io/library/caddy:2-alpine`.

Сайт статический: сборки, Node.js и npm для деплоя не требуется. Если используешь `npx` для правок проекта, `.npmrc` задаёт публичный `https://registry.npmjs.org/`.

## Подготовка

Выполняй команды на виртуалке в Bash. Сначала клонируй репозиторий под своим обычным пользователем:

```sh
git clone https://github.com/Vinatorul/wedding_site.git
cd wedding_site
```

Если репозиторий закрытый, заранее настрой на виртуалке доступ к GitHub, например SSH-ключ, и используй SSH-адрес репозитория. Не записывай токены или приватные ключи в файлы проекта.

Посмотри список контейнеров:

```sh
sudo env DOCKER_API_VERSION=1.43 docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

Найди Caddy, который обслуживает порты 80 и 443. Заполни параметры в терминале; они не попадут в репозиторий:

```sh
read -rp 'Домен сайта без https://: ' SITE_DOMAIN
read -rp 'Имя общего Caddy-контейнера: ' PROXY_CONTAINER
sudo env DOCKER_API_VERSION=1.43 docker inspect "$PROXY_CONTAINER" \
  --format '{{json .NetworkSettings.Networks}}'
sudo env DOCKER_API_VERSION=1.43 docker inspect "$PROXY_CONTAINER" \
  --format '{{json .Mounts}}'
read -rp 'Docker-сеть общего прокси: ' PROXY_NETWORK
read -rp 'Полный путь к Caddyfile на виртуалке: ' CADDY_FILE
```

В первом выводе возьми имя сети, во втором — `Source` у Caddyfile. Если смонтирован каталог, допиши имя файла внутри него. Параметр `--caddyfile` принимает путь на виртуалке; путь внутри контейнера скрипт определит сам.

В этих командах `DOCKER_API_VERSION=1.43` обеспечивает совместимость с Docker на текущей виртуалке. На другом сервере с более новым Docker этот параметр можно убрать.

## Первый запуск

```sh
sudo env DOCKER_API_VERSION=1.43 python3 scripts/deploy-vm.py \
  --domain "$SITE_DOMAIN" \
  --network "$PROXY_NETWORK" \
  --proxy-container "$PROXY_CONTAINER" \
  --caddyfile "$CADDY_FILE"
```

По умолчанию контейнер называется `wedding-site-web`, а файлы хранятся в `/srv/wedding-site`. Если эти имена уже используются, передай свободные через `--container` и `--deploy-root`. Каталог деплоя должен быть отдельным, вне репозитория.

Скрипт копирует `dist/` в новый каталог `releases/`, переключает ссылку `current` и проверяет ответ контейнера по HTTP. Перед изменением общего Caddyfile он сохраняет копию в `config-backups/`. Затем проверяет конфигурацию Caddy и перезагружает её без остановки прокси.

Если домен уже настроен вне блока этого скрипта или имя контейнера занято другим приложением, запуск остановится с пояснением. При ошибке проверки или применения конфигурации скрипт возвращает прежние файлы и пытается восстановить настройку Caddy. Если откат Caddy тоже не удался, это отдельно появится в выводе; путь к резервной копии находится в `/srv/wedding-site/config-backups/`.

Общий Caddyfile обновляется на месте. Это нужно, когда Docker монтирует отдельный файл: замена файла через `mv` или редактор с атомарным сохранением может оставить прокси на старой версии.

## Проверка домена и HTTPS

DNS-запись A должна указывать на публичный IPv4 виртуалки. Если есть AAAA, она тоже должна вести на этот сервер по доступному IPv6. Снаружи должны быть доступны порты 80 и 443, а у общего Caddy должны сохраняться данные сертификатов между запусками. При добавлении домена Caddy сам получает сертификат — см. [условия автоматического HTTPS](https://caddyserver.com/docs/automatic-https).

После деплоя проверь сайт:

```sh
dig +short A "$SITE_DOMAIN"
dig +short AAAA "$SITE_DOMAIN"
curl --fail --head "https://${SITE_DOMAIN}/"
```

Проверка внутри скрипта подтверждает работу контейнера сайта. Внешний DNS и выдачу сертификата проверяет последняя команда. Если HTTPS не открылся, посмотри логи общего прокси и сайта:

```sh
sudo env DOCKER_API_VERSION=1.43 docker logs --tail 100 "$PROXY_CONTAINER"
sudo env DOCKER_API_VERSION=1.43 docker logs --tail 100 wedding-site-web
```

Если передавал другое имя через `--container`, подставь его и здесь.

## Обновление

В каталоге репозитория выполни:

```sh
git pull --ff-only
sudo env DOCKER_API_VERSION=1.43 python3 scripts/deploy-vm.py \
  --domain "$SITE_DOMAIN" \
  --network "$PROXY_NETWORK" \
  --proxy-container "$PROXY_CONTAINER" \
  --caddyfile "$CADDY_FILE"
```

Используй те же параметры, что при первом запуске, включая `--container` и `--deploy-root`, если менял их. В новом сеансе терминала снова задай четыре переменные из раздела подготовки. Можно сохранить параметры в собственный файл на виртуалке вне репозитория; скрипт сам такие файлы не читает.

Повторный запуск использует тот же контейнер и обновляет только свой блок в Caddyfile. Старые версии файлов и резервные копии остаются в каталоге деплоя; скрипт не удаляет их автоматически. Если скрипт другого приложения заменил весь общий Caddyfile, повторный деплой приглашения вернёт его блок. Чтобы это не повторялось, скрипты других приложений тоже должны сохранять соседние домены.

## Возврат предыдущей версии сайта

Выбери прежний каталог в `/srv/wedding-site/releases/` и переключи ссылку. В команде ниже замени `ИМЯ_РЕЛИЗА` на имя нужного каталога:

```sh
sudo python3 - /srv/wedding-site ИМЯ_РЕЛИЗА <<'PY'
import os
from pathlib import Path
import sys

root = Path(sys.argv[1])
release = root / "releases" / sys.argv[2]
if release.parent != root / "releases" or not (release / "index.html").is_file():
    raise SystemExit("Не найден выбранный релиз")
temporary = root / ".current-rollback"
temporary.symlink_to(f"releases/{release.name}")
os.replace(temporary, root / "current")
PY
```

Если каталог деплоя другой, замени и `/srv/wedding-site`. Для возврата файлов перезапуск контейнера или Caddy не нужен. Этот способ не меняет домен и конфигурацию прокси.

Анкета на сайте пока проверяет заполнение, но не отправляет и не сохраняет ответы. Деплой не подключает отправку. Контакты команды и дресс-код также требуют уточнения перед рассылкой приглашения.

Проверить сам скрипт без виртуалки можно командой `python3 -m unittest discover -s tests -v`. Она проверяет операции с настоящими временными файлами и моделирует команды Docker; для проверки живого Caddy нужен запуск на сервере.
